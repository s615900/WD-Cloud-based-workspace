## 0. 現況與事實基礎

### 0-1 C 的症狀（iPhone Safari，`asset-manager-s615900.replit.app` 行事曆頁）

實機截圖顯示：

1. 深藍 header（`個人工作台`）**未延伸到螢幕右緣**，約在 62% 處截斷
2. 「班別模板」卡片列被裁切，第三張卡片只露出一半
3. 頁面右側出現橫向捲軸
4. 月檢視 7 欄擠在窄寬度內，日期格與事件標籤過小

**判讀：症狀 1 是結果不是原因。** header 若為 `width:100%`，其寬度基準是視窗寬；當頁面內有元素橫向撐開 `body`，body 變得比視窗寬、產生橫向捲動，header 就只會有視窗寬，視覺上像是「被切掉」。所以真正要修的是那個**橫向溢出源**（最可能是班別模板卡片列或月曆表格的 `min-width`），不是 header 的 CSS。

**明確禁止的修法：** 不得用 `overflow-x: hidden`、`body { width: 100vw }`、或調整 `<meta viewport>` 的 `initial-scale` 來遮蓋症狀。那是把溢出藏起來，橫向捲軸消失但內容仍被裁掉。

## 1. 工單 C｜手機版響應式修復

### 1-1 主積木

- `public/desktop/calendar.html` 及其樣式（實際檔名以專案實查為準）
- 共用的版面／header 樣式檔

### 1-2 第一步：定位溢出源（先量測，再改 CSS）

在 iPhone Safari 或 DevTools 手機模擬（390×844）下執行：

```js
const vw = document.documentElement.clientWidth;
console.log('scrollWidth', document.documentElement.scrollWidth, 'clientWidth', vw);
[...document.querySelectorAll('*')]
  .map(el => ({ el, r: el.getBoundingClientRect() }))
  .filter(({ r }) => r.right > vw + 1 || r.left < -1)
  .forEach(({ el, r }) =>
    console.log(Math.round(r.left), Math.round(r.right), el.tagName, el.className));
```

**把這段的輸出貼回來，作為修改依據。** 沒有這份輸出就開始改 CSS 一律視為未完成。

常見元凶（依可能性排序，仍以量測為準）：

- flex 子項預設 `min-width: auto`，導致內容撐開容器 → 父層或該子項補 `min-width: 0`
- 卡片列用 `display: flex` 但沒有 `overflow-x: auto`，整列直接把容器撐寬
- 表格或格線設了固定 `min-width`
- 元素同時有 `width: 100%` 與左右 `padding` 但缺 `box-sizing: border-box`

### 1-3 實作內容

**(1) 消除橫向溢出**
依 1-2 的量測結果修正實際溢出的元素。修完後 `document.documentElement.scrollWidth` 必須等於 `clientWidth`。

**(2) 班別模板卡片列**
改為明確的橫向捲動容器：容器 `overflow-x: auto`、`scroll-snap-type: x mandatory`，卡片 `flex: 0 0 auto` + `scroll-snap-align: start`，容器本身寬度不得超過父層。加上 `-webkit-overflow-scrolling: touch`。

**(3) 月曆檢視在窄螢幕的處理**
`≤ 768px` 時預設切到「週」檢視（該切換鈕已存在）。「月」仍可手動選擇，但月檢視需放進獨立的橫向捲動容器，不得撐開頁面。日期格內的事件標籤超出時以省略號截斷，不換行撐高。

**(4) 觸控目標**
`月／週／上頁／今天／下頁`、`開放預約／分享空檔` 等按鈕最小點擊區 44×44px。

**(5) header**
確認為 `width: 100%`；1-2 修好後應自動延伸到右緣。若仍未滿版，代表還有第二個溢出源，回到 1-2 重測，**不要對 header 單獨補寬度**。

### 1-4 不可動的部分

- 桌面版（≥1024px）現有版面，不得因手機修正而位移
- 空檔推算演算法、`/api/roster/*` 任何行為
- 個人系統配色（不得引入接案系統的 `#0B3D5C` / `#D8A54B`）
- 資料層與 Ragic 任何欄位

### 1-5 驗收條件（實機 iPhone Safari，非 DevTools 模擬）

1. 行事曆頁 console 執行 `document.documentElement.scrollWidth === document.documentElement.clientWidth` → `true`
2. 深藍 header 延伸至螢幕右緣，無截斷
3. 頁面無橫向捲軸；班別模板列可獨立橫向滑動且有 snap 手感
4. 直向 390px 下預設顯示週檢視；手動切月檢視時頁面仍不產生橫向捲軸
5. 橫向轉直向、直向轉橫向各切換一次，版面不破
6. 桌面 1440px 下截圖與修改前逐項比對，無非預期位移
7. 附實機截圖，不接受僅以 DevTools 模擬器截圖交付
