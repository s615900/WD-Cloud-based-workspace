## 編號修正說明（v2.0）

v1.0 文件使用「Step 1」「Step 2」「Step 8」「Step 1-12」「Step 9-12」等步驟編號。經查證 repo 原始碼、`git log`、`docs/` 資料夾內所有文件，均不存在對應此編號的「Step 1–12」拆解清單，此編號體系為誤植，來源不明。

實際可查證的驗收依據為 `docs/02-Claude-Code實作指示-行事曆.md` 第九節「驗收標準（12 項）」，共 12 項，逐項附有編號、驗收內容與所需證據。v1.0 中的「#1／#2／#8」應解讀為此 12 項中的第 1、2、8 項，而非獨立的「Step」編號。

v2.0 全面移除「Step」表述，改以「驗收標準第 N 項」稱呼。先前提出的「路由檔 ↔ Step 對應」推測表（`rosterTemplates.ts` ↔「Step 1」、`rosterSchedule.ts` ↔「Step 2」）已確認為未經證實的猜測，予以作廢，不再採用，本文件不含任何反推內容。

此外，經連動判定分析，驗收標準第 1、2、8 項之間存在執行順序與回歸相依關係：

- 第 1 項須先於第 2 項驗證（第 2 項新增模板後列表筆數會變動，順序顛倒會誤判第 1 項失敗）
- 第 2 項驗完須回頭確認第 1 項的列表與排序仍正確，並抽查第 3 項（單日套用）
- 第 8 項（調整緩衝與最短空檔）與第 9 項（PATCH 回 Ragic 仍只有一筆）是同一條寫入路徑，須合併驗證
- 第 8 項須回歸第 6 項（跨日夜班扣除空檔）與第 7 項（取消變回空檔），因三者共用同一套空檔推算輸入參數

v2.0 依此重新排定執行順序為：第 1 項 → 第 2 項（+回歸第 1 項、抽查第 3 項）→ 第 8 項（+強制第 9 項、回歸第 6、7 項）→ 全批結束後補驗第 11 項。

### 4. 可實機操作的驗收條件

全程開啟瀏覽器 DevTools → Network 分頁，勾選 Preserve log。

**A-1 月檢視載入**
1. 桌機瀏覽器開啟 `asset-manager-s615900.replit.app/desktop/calendar.html`
2. 頁面預設顯示當月（2026 年 8 月）
3. Network 出現 `GET /api/roster/...`，狀態 **200**，Response 為含資料的 JSON（不是空陣列、不是 HTML 錯誤頁）
4. 畫面上實際渲染出有資料的日期格
   - 📸 **截圖 1**：整頁月檢視 + Network 分頁同框

**A-2 週檢視切換**
1. 切至週檢視
2. 顯示的日期區間與當前週相符（起訖日期人工核對，不看程式邏輯）
3. Network 有對應請求且回應 200
   - 📸 **截圖 2**：週檢視畫面

**A-3 日面板**
1. 點擊任一「已知有行程」的日期
2. 日面板開啟，顯示的行程內容與 Ragic 後台該日資料**逐筆核對一致**
3. 點擊空白日期，面板正常開啟且顯示空狀態（不得白畫面或報錯）
   - 📸 **截圖 3**：日面板展開狀態

**A-4 空檔規則寫入（最關鍵，最容易假成功）**
1. 於空檔規則表單新增一筆規則，內容自訂但需可辨識（例如備註填 `驗證-0828`）
2. 送出後 Network 出現 `POST`，狀態 **200**
3. **前端顯示成功不算數** — 直接開 Ragic 後台，找到該筆記錄
4. 確認每一個欄位都有值，**特別檢查沒有出現「看起來存了但欄位是空的」**（此為本專案重複踩過的 Ragic 地雷）
5. 確認時間欄位格式為 `yyyy/MM/dd HH:mm:ss`（24 小時制、含秒）
6. 瀏覽器整頁重新整理（F5），該筆規則仍在畫面上
   - 📸 **截圖 4**：Ragic 後台該筆記錄，欄位值清楚可讀
   - 📸 **截圖 5**：重新整理後仍存在的前端畫面

**A-5 分享空檔 — dryRun**
1. 點「分享空檔」，確認實際打出的是 `POST /api/roster/publish?dryRun=1`
2. 回應 200，內容為預覽文字
3. **手機 LINE 不得收到任何訊息**（等待至少 60 秒確認）
   - 📸 **截圖 6**：Network Response 的預覽文字

**A-6 分享空檔 — 實際推送**
1. 以非 dryRun 方式觸發公布
2. 手機 LINE「代辦小幫手」收到文字訊息
3. 訊息內容與 A-5 的 dryRun 預覽**完全一致**（逐字比對，含換行與符號）
4. 訊息中的日期／時段與 Ragic 實際空檔資料相符
   - 📸 **截圖 7**：手機 LINE 收到的訊息（手機實拍或截圖）

**A-7 開放預約**
1. 點「開放預約」，確認 Network 請求成功
2. 至 Ragic 確認對應狀態欄位確實被更新
   - 📸 **截圖 8**：Ragic 狀態欄位變更後

### 通過標準
A-1 至 A-7 **全部**通過即完成本附錄驗證。此附錄非本批（工單一～四）之前置阻塞項，通過與否不影響工單一～四的執行，可獨立排入介面整體回歸時驗證。任一項失敗即停止，記錄現象後另開修正工單。
