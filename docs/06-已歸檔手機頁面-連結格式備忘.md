# 已歸檔手機頁面：分享／預約連結格式備忘

檔名原訂 `04-已歸檔手機頁面-連結格式備忘.md`，跟既有 `04-行事曆模組-實機驗證工單.md` 撞號，改用 `06-` 前綴。

## 背景

行動版 PWA 六頁（index／schedule／calendar／settings／search／add）已歸檔到
`_archive/mobile-pwa/`（見 commit `eb96beb`）。`calendar.html` 裡原本有「分享空檔」
「開放預約」兩顆按鈕，會在畫面上顯示一組固定連結給使用者複製；這份文件把當時的
邏輯抄下來備查，內容全部核對自 `_archive/mobile-pwa/calendar.html`，不是憑印象寫的。

## 結論（回答「連結是不是後端組的」）

`buildPublishText()` / `buildShortPublishText()`（`src/ragic/publish.ts`）組出來的
LINE 推播文字**確實包含**開放預約連結（`▸ 預約：${bookingUrl}` 這行），但這個
`bookingUrl` 是從 Ragic 空檔設定（`/ragicforms21/7`「預約連結」欄位，field id
`1001415`）讀出來的，管理者透過**桌面版** `public/desktop/calendar.html` 的
「空檔推算規則」表單手動填入（`src/routes/freeSlotConfig.ts` PATCH `/api/roster/config`
寫入）。這條路徑跟手機版 `calendar.html` 完全無關，歸檔不影響它。

手機版 `calendar.html` 裡另外那兩顆「分享空檔」「開放預約」按鈕，邏輯是**純前端字串
組合**，不呼叫任何 API、不讀寫 Ragic，如下。

## 原始邏輯（逐字抄自 `_archive/mobile-pwa/calendar.html`）

### 分享空檔（`share.html`）— 第 1059–1076 行

```js
// 固定連結、不帶 dates 參數：share.html 會呼叫 /api/share 拿「今天以後」全部空檔，
// 之後在行事曆新增或刪除空檔，同一個連結打開永遠是最新資料，不用每次重新產生。
var link = location.origin + "/share.html";
```

按下「分享空檔」按鈕→把 `location.origin + "/share.html"` 塞進一個唯讀輸入框顯示
給使用者→「複製連結」按鈕呼叫 `navigator.clipboard.writeText()`（失敗則退回
`document.execCommand("copy")`）。

### 開放預約（`book.html`）— 第 1089–1100 行

```js
// 開放預約（book.html）：一樣是固定連結、不帶參數，對方打開後可以直接選時段＋填名字送出，
// 跟上面純參考用的 share.html 分開，資料一樣即時抓 /api/book。
var link = location.origin + "/book.html";
```

同一套「顯示到輸入框＋複製到剪貼簿」流程，按鈕 id 是 `book-btn` / `copy-book-link-btn`。

## 網址格式與參數

| 連結 | 格式 | Query 參數 | 目的頁實際打的 API |
|---|---|---|---|
| 分享空檔 | `<origin>/share.html` | 無 | `GET /api/share`（`public/share.html:174`） |
| 開放預約 | `<origin>/book.html` | 無 | `GET /api/book`（`public/book.html:344`），送出預約走 `POST /api/book/:id`（`public/book.html:465`） |

兩條連結都是「網域 + 固定路徑」，不帶任何 query string 或動態片段——所以連結本身
不會因為刪除 `calendar.html` 而失效或改變，唯一消失的是「在手機版行事曆頁點一下
按鈕就能看到／複製這兩個網址」這個小工具。`book.html`／`share.html` 這兩個頁面本身
未被歸檔，仍正常運作。
