# 05 — 空檔推算單元測試案例（Claude Code 草擬，待核對）

> 這是依 `02` 文件第五節演算法本體 + 六行案例摘要重新定義的具體測試案例。
> **測試用的 FreeSlotConfig 數值是我為了讓案例可驗證而假設的固定值，不代表 `/7`
> 空檔設定表的實際生產數值** —— 單元測試本來就該用固定 fixture，不吃真實 Ragic 資料。

## 共用測試 fixture

```ts
interface ScheduleEntry {
  start: string;   // "HH:mm"
  end: string;     // "HH:mm"
  allDay: boolean;
  status: string;  // "正常" | "取消"
}

interface FreeSlotConfig {
  dayStart: string;     // "HH:mm"
  dayEnd: string;       // "HH:mm"
  bufferBefore: number; // 分鐘
  bufferAfter: number;  // 分鐘
  minSlot: number;      // 分鐘
  roundTo: number;      // 分鐘
}

const CONFIG: FreeSlotConfig = {
  dayStart: "05:00",
  dayEnd: "23:00",
  bufferBefore: 30,
  bufferAfter: 60,
  minSlot: 60,
  roundTo: 30,
};

function computeFreeSlots(
  todaySchedule: ScheduleEntry[],
  prevDaySchedule: ScheduleEntry[],
  config: FreeSlotConfig,
): { start: string; end: string }[];
```

---

## 案例 1：一般日

輸入：`todaySchedule = [{ start: "05:30", end: "14:30", allDay: false, status: "正常" }]`
（駿斯早班），`prevDaySchedule = []`

推算：busy 原始 `[05:30,14:30]` → 套緩衝 `[05:00,15:30]`（05:30-30分＝05:00，剛好卡在
`dayStart`，14:30+60分＝15:30）→ 窗口 `[05:00,23:00]` 內只剩一段補集 `[15:30,23:00]` →
對齊（30分）不變 → 長度 450 分 ≥ minSlot。

**預期輸出**：`[{ start: "15:30", end: "23:00" }]`

---

## 案例 2：跨日夜班

輸入（計算 D+1 日的空檔）：`todaySchedule = []`（D+1 當天沒有自己的行程），
`prevDaySchedule = [{ start: "22:00", end: "06:00", allDay: false, status: "正常" }]`
（D 日夜班跨到隔天）

推算：D 日夜班原始結束 `06:00`，因為 `e<=s`（跨日）判定，帶入 D+1 的 1b 規則
`push {s:0, e:06:00 原始值}` → 套緩衝：`bufferBefore` 讓起點變負值（視同觸及窗口下界），
`bufferAfter` 60 分讓終點變 `07:00` → 窗口 `[05:00,23:00]` 內補集只剩 `[07:00,23:00]`。

**預期輸出**：`[{ start: "07:00", end: "23:00" }]`
（隔日早上到 07:00 為止都算佔用，符合「含班後緩衝」）

---

## 案例 3：緩衝後重疊（合併成一段）

輸入：`todaySchedule = [`
  `{ start: "09:30", end: "13:30", allDay: false, status: "正常" },`（迪卡儂早早）
  `{ start: "14:00", end: "22:00", allDay: false, status: "正常" }`（拍攝賽事）
`]`，`prevDaySchedule = []`

推算：兩段套緩衝後為 `[09:00,14:30]` 與 `[13:30,23:00]`，`13:30 < 14:30` → 重疊，合併成
`[09:00,23:00]`。窗口 `[05:00,23:00]` 補集只剩前段 `[05:00,09:00]`，長度 240 分 ≥ minSlot；
合併後段與 dayEnd 齊平，無後段空檔。

**預期輸出**：`[{ start: "05:00", end: "09:00" }]`
（重點斷言：兩段班之間**不會**出現任何空檔，證明有正確合併而非誤判出負長度區間）

---

## 案例 4：全天行程

輸入：`todaySchedule = [{ start: "00:00", end: "00:00", allDay: true, status: "正常" }]`，
`prevDaySchedule = []`

推算：`allDay=true` → 直接 push `{s:0, e:1440}`，整個窗口都被佔用。

**預期輸出**：`[]`

---

## 案例 5：碎片過濾（含四捨五入方向驗證）

輸入：`todaySchedule = [`
  `{ start: "07:00", end: "09:00", allDay: false, status: "正常" },`
  `{ start: "11:10", end: "15:00", allDay: false, status: "正常" }`
`]`，`prevDaySchedule = []`

推算：套緩衝後為 `[06:30,10:00]` 與 `[10:40,16:00]`，不重疊，中間留下原始 40 分鐘的縫
`[10:00,10:40]`。對齊：起點無條件進位 `10:00→10:00`（已是 30 分倍數），終點無條件捨去
`10:40→10:30`，對齊後只剩 30 分鐘 `<` `minSlot`(60) → **這段必須被濾掉、不得出現在結果裡**。

窗口內其餘兩段：`[05:00,06:30]`（90 分）與 `[16:00,23:00]`（420 分）皆 ≥ minSlot，保留。

**預期輸出**：`[{ start: "05:00", end: "06:30" }, { start: "16:00", end: "23:00" }]`
（中間 10:00–10:30 那段**不得出現**，用來斷言碎片過濾生效）

---

## 案例 6：取消狀態不佔用

輸入：`todaySchedule = [{ start: "10:00", end: "12:00", allDay: false, status: "取消" }]`，
`prevDaySchedule = []`

推算：狀態＝取消，步驟 0 直接排除，不進入 busy 清單 → 整個窗口都是空檔。

**預期輸出**：`[{ start: "05:00", end: "23:00" }]`
